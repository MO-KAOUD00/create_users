# مشروع: إنشاء مستخدمين تلقائيًا من ملف CSV (Bash Automation)

مشروع من سلسلة **Linux Admin 1** — سكريبت Bash بيقرأ بيانات مستخدمين من ملف CSV، وينشئهم تلقائيًا على السيرفر (Users + Groups + Passwords)، بدل ما الأدمن يعمل كل ده يدويًا واحد واحد.

---

## 📌 وصف المهمة (Task Description)

في بيئة العمل الحقيقية، لما تنضم مجموعة موظفين جدد لشركة، الـ Admin مش بيقعد يعمل `useradd` يدوي لكل موظف. بدل كده، بياخد ملف بيانات (زي CSV) من الـ HR، ويشغل عليه سكريبت يعمل الآتي تلقائيًا لكل مستخدم:

1. يتأكد إن الـ Group بتاعه موجود، ولو مش موجود يعمله
2. يتأكد إن المستخدم مش موجود بالفعل (يتجنب التكرار)
3. ينشئ المستخدم مع مجلد Home واسم كامل و Shell محدد
4. يولّد باسورد عشوائي وآمن لكل مستخدم
5. يجبر المستخدم يغيّر الباسورد بتاعه أول ما يسجل دخول
6. يسجل كل خطوة في ملف Log للمراجعة

### المتطلبات (Requirements)
- صلاحيات root لتشغيل السكريبت
- ملف `users.csv` بصيغة: `username,fullname,group,shell`

## 🖥️ السكريبت: `create_users.sh`

السكريبت الكامل موجود في ملف منفصل `create_users.sh` في نفس الريبو. بيقوم بالخطوات التالية:

1. يتأكد إن السكريبت شغال بصلاحيات root
2. يتأكد إن ملف `users.csv` موجود
3. يقرأ الملف سطر سطر (متجاهلًا الـ Header والأسطر الفاضية)
4. لكل سطر:
   - ينشئ الـ Group لو مش موجود
   - يتخطى المستخدم لو موجود بالفعل
   - ينشئ المستخدم مع مجلد Home واسم كامل و Shell محدد
   - يولّد باسورد عشوائي ويطبقه
   - يجبر المستخدم يغيّر الباسورد أول ما يسجل دخول
5. يسجل كل خطوة في ملف `users_creation.log`

## ⚙️ خطوات التشغيل

```bash
mkdir ~/user-creation-project
cd ~/user-creation-project
nano users.csv        # حط فيه البيانات
nano create_users.sh  # الصق فيه السكريبت

chmod +x create_users.sh   # اديله صلاحية تنفيذ
sudo ./create_users.sh     # شغله بصلاحيات root
```

## 🐞 مشكلة واجهتنا أثناء التنفيذ (Troubleshooting)

بعد أول تشغيل، ظهر الخطأ التالي:

```
./create_users.sh: line 61: echouser created : ahmed |group: developers | Password: aFewaWHe+mk=: command not found
```

**السبب:** مفيش مسافة بين `echo` وعلامة الاقتباس `"` في السطر (`echo"..."` بدل `echo "..."`)، فالـ Shell فهم الاثنين كأمر واحد مش موجود.

**الحل:** إضافة مسافة بعد `echo` مباشرة:
```bash
echo "✅ تم إنشاء المستخدم: $username | الجروب: $groupname | Password: $random_pass" | tee -a "$LOG_FILE"
```

**ملحوظة:** المستخدمين والجروبات كانوا اتعملوا بنجاح فعلًا رغم الخطأ، لأن المشكلة كانت بس في سطر طباعة الرسالة، مش في منطق إنشاء المستخدم نفسه.

**نصيحة للمستقبل:** فحص السكريبت قبل التنفيذ بأمر:
```bash
bash -n create_users.sh
```

## ❓ الأسئلة والأجوبة (Q&A) أثناء بناء المشروع

### 1. إيه هو ملف الـ CSV؟
CSV (Comma-Separated Values) هو ملف نصي بسيط بيخزن بيانات جدولية، وكل عمود بيتفصل عن التاني بفاصلة (,)، وكل سطر يمثل صف جديد. بيتستخدم عشان تجهز بيانات مستخدمين كتير (زي من الـ HR) وتخليها Input لسكريبت بدل ما تكتب كل مستخدم يدوي.

### 2. إزاي أجهز ملف الـ CSV؟
3 طرق رئيسية:
- **يدوي** بمحرر نصوص زي `nano`/`vim`
- من **Excel/Google Sheets** بحفظه بصيغة CSV
- **توليده بسكريبت** لبيانات وهمية للتجربة، مثلًا:
  ```bash
  echo "username,fullname,group,shell" > users.csv
  for i in {1..10}; do
    echo "user$i,Test User $i,developers,/bin/bash" >> users.csv
  done
  ```

### 3. إيه معنى `EUID`؟
متغير مدمج في Bash بيمثل الرقم التعريفي (ID) للمستخدم اللي بينفذ العملية **حاليًا** (Effective User ID). المستخدم root دايمًا EUID بتاعه = 0. بنستخدمه للتأكد إن السكريبت شغال بصلاحيات root قبل تنفيذ أوامر حساسة زي `useradd`:
```bash
if [[ $EUID -ne 0 ]]; then
   echo "لازم تشغل السكريبت بصلاحيات root"
   exit 1
fi
```

### 4. إيه معنى `IFS`؟
Internal Field Separator — بيحدد لـ Bash إزاي يفصل الكلمات وقت قراءة سطر نص. افتراضيًا بيفصل بالمسافة، لكن ملفات CSV مفصولة بفاصلة، فبنستخدم:
```bash
while IFS=',' read -r username fullname groupname shell
```
عشان كل عمود في السطر يترمي في متغير منفصل بدل ما السطر كله يترمي في متغير واحد.

### 5. إيه فايدة أمر `tee`؟
بيطبع الـ Output على الشاشة **وفي نفس الوقت** يحفظه في ملف. من غيره لازم تختار واحدة بس (إما تشوفه أو تحفظه). الخيار `-a` (append) بيضيف السطر الجديد في آخر الملف من غير ما يمسح القديم:
```bash
echo "تم إنشاء المستخدم" | tee -a log.txt
```

### 6. إيه معنى `-z`؟
اختبار شرطي بيتأكد هل النص فاضي ولا لأ:
- `-z "$var"` → true لو المتغير **فاضي**
- `-n "$var"` → true لو المتغير **فيه قيمة** (عكسها)

بنستخدمها عشان نتجاهل أي سطر فاضي بالغلط في ملف الـ CSV:
```bash
if [[ -z "$username" ]]; then
    continue
fi
```

### 7. إيه فايدة `getent group` و `id` في السكريبت؟
- `getent group "$groupname"` → يدور على الجروب في قاعدة بيانات النظام. لو مش لاقيه (باستخدام `!` للنفي)، السكريبت يعمل الجروب بـ `groupadd`.
- `id "$username"` → يتأكد هل المستخدم موجود بالفعل. لو موجود، السكريبت يطبع تحذير ويعمل `continue` عشان يتخطى المستخدم ده ومايكررهوش.

الترتيب مهم: بنتأكد من الجروب الأول عشان `useradd -g` محتاج الجروب يكون موجود، وبعدين بنتأكد من المستخدم عشان مانكررش الإنشاء.

### 8. إيه فايدة `-m` و `-c` في `useradd`؟
- `-m` → ينشئ مجلد Home تلقائي للمستخدم (زي `/home/ahmed`) وينسخله ملفات إعداد افتراضية من `/etc/skel`
- `-c "النص"` → يحط اسم/وصف كامل للمستخدم في حقل GECOS بملف `/etc/passwd`، مفيد جدًا لما يكون عندك عشرات المستخدمين وعايز تعرف كل username تابع لمين

### 9. إيه فايدة `openssl rand`، `chpasswd`، و `chage`؟
- **`openssl rand -base64 8`** → يولّد باسورد عشوائي وآمن (تشفيريًا) لكل مستخدم جديد، بدل باسورد ثابت وضعيف
- **`chpasswd`** → يطبّق الباسورد على المستخدم مباشرة من غير تفاعل يدوي (مناسب للأتمتة)، عكس `passwd` العادي اللي بيطلب إدخال يدوي
- **`chage -d 0`** → يخلي تاريخ آخر تغيير للباسورد = صفر، يعني يجبر المستخدم يغيّر باسورده فور أول تسجيل دخول. ده معيار أمني مهم عشان الباسورد المؤقت (اللي ظهر في اللوج) ميفضلش صالح للاستخدام بعد أول مرة

## 🎯 الدروس المستفادة (Key Takeaways)

- التعامل مع ملفات CSV كمصدر بيانات للأتمتة (Automation)
- إدارة المستخدمين والجروبات برمجيًا (`useradd`, `groupadd`, `getent`, `id`)
- أساسيات الأمان: باسوردات عشوائية + إجبار تغييرها أول Login (`chage`)
- كتابة Logs احترافية لتتبع تنفيذ السكريبتات (`tee -a`)
- قراءة رسائل الأخطاء وتشخيصها (`command not found` بسبب مسافة مفقودة)
- فحص صحة السكريبت قبل التنفيذ (`bash -n`)
